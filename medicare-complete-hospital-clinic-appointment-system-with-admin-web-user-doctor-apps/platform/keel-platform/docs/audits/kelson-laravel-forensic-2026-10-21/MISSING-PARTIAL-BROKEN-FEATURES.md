## 3. The BROKEN capabilities (defects, not gaps)

**None are recorded in the matrix** — the matrix records implementation and proof, not
runtime breakage. This audit found the runtime breakage, and it lives in the findings
register instead:

| Finding | The broken behaviour | Where |
|---|---|---|
| KFA-005 | the reference host **aborts during boot** with a stack overflow — the real boot path, not the harness path | `runtime/kelson-demo/src/lib.rs` |
| KFA-001 | the WASM sandbox runs on a compiler with **two critical miscompilation advisories** | `crates/extension/wasm` |
| KFA-002 | a guest's handle tables are **charged to no limit** | `crates/extension/wasm` |
| KFA-003 | the TLS client can be driven into a **1 GiB pre-auth allocation** and leaks session secrets to a `Debug` log | `crates/services/http-client` |
| KFA-004 | the TLS trust store **accepts distrusted intermediates** | `crates/services/http-client` |
| KFA-006 | a deployment that omits one config key **boots on a volatile in-memory store** | `crates/application/configuration` |
| KFA-015 | the local disk driver performs **blocking file IO on the async executor** | `adapters/kelson-storage-local` |

**The distinction matters:** a missing capability is a product decision; a broken capability
is a defect that makes the shipped promise untrue. The audit found seven of the second kind,
and they outrank every parity gap in the roadmap because a framework that lies about what it
does is not competitive at any coverage level.
