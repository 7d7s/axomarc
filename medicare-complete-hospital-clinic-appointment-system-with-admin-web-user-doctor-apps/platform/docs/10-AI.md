# 10 — AI

The AI surface (S6) is four crates under `crates/ai/`: client, tools, agents, mcp.

## The rule that governs everything

The execution path is fixed: **AI Agent -> Tool -> Execution -> Capability -> Scope -> Policy ->
Command**. An agent never gains elevated authority. Every tool call executes through the engine
under the caller principal; a denied tool is reported back to the model as a tool error and is
never retried with different credentials.

## kelson-ai — provider port

`AiClient` trait: `complete(request)` and `embed(input)`. Message/role/tool-call types are
framework-owned so providers stay swappable. `StubAiClient` plays scripted turns deterministically
(dev/test, D-67); live providers plug in behind the same port. `deterministic_embedding` gives
stable, normalized embeddings for tests without a provider.

## kelson-ai-tools — tools from contracts

A `ToolSpec` binds a model-visible name to exactly one operation, with the capability metadata
mirrored from the operation. Tools are generated from `Command`/`Query` contracts
(`ToolSpec::for_command::<C>`, `for_query::<Q>`) — never hand-wired around them.

## kelson-ai-agents — the runtime

`AgentRuntime` runs the loop: model proposes tool calls, each call resolves to a registered tool,
executes through the engine with a deterministic idempotency key (`agent-{execution}-{call}`), and
the result flows back to the model. A step budget stops runaway loops; unknown tools and missing
handlers surface as structured tool errors.

## kelson-ai-mcp — MCP surface

The MCP manifest is generated from the same contracts: `generate_manifest(name, version, tools)`
emits `{ name, version, tools: [{ name, description, inputSchema }] }`; `tools_from_graph` derives
one tool per registered operation from the compiled platform graph. MCP describes what exists — it
grants nothing; authorization still happens in the engine at call time.

```bash
kelson mcp:tools                 # table of generated MCP tools
kelson mcp:tools --format json   # the manifest itself
```

## Search integration

Document embeddings for `services/search` vector/hybrid queries come from the same `AiClient`
port (or `deterministic_embedding` in tests).
